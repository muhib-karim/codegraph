# codegraph explorer - v0.2 design addendum

Status: design proposal, 2026-09-25. This adds a local visual layer; it does not change the v0.1 index, schema, four query commands, JSON/eval contract, or language coverage. Implementation starts only after review. All code, styling, icons, and layouts are original MIT work; no GitNexus source or assets are used.

## Decision: local server with a static frontend and bounded query API

Ship a small Python HTTP server (`codegraph explore --repo DIR [--db PATH] [--port PORT]`) serving bundled HTML/CSS/JS and a read-only JSON API on **127.0.0.1 only**. The server opens the existing LadybugDB graph in read-only mode and delegates callers/inherits/dead-code/blast to the same query functions as the CLI. The browser never opens the DB file. Initial implementation can use Python's standard-library HTTP server and dependency-free SVG/Canvas rendering; avoid framework and bundler requirements until graph size or UX warrants them. Frontend assets live under `codegraph/web/` and are packaged with the Python distribution. `explore` is a new command, not a revision of existing command output.

Why not a full JSON export/static site for v0.2: a repository can have many symbols and call edges, while the UI needs a small neighborhood around a selected symbol. Exporting everything makes the initial load large, duplicates query logic in JavaScript, risks stale snapshots, and exposes a portable copy of potentially private graph data. A standalone snapshot export can be added later as an explicit, versioned, opt-in artifact, not the default browsing path. The local server provides interactive queries with one authoritative set of semantics and keeps source and graph on the owner's machine. No hosted service, external CDN, telemetry, LLM, or runtime network dependency.

The server is a read-only *viewer*, not a general Cypher endpoint or source-code edit API. It must reject non-loopback binding by default and not provide a remote-binding flag in v0.2. On startup, check the DB schema version and metadata; display indexed time, commit, repo path (locally), file/symbol/edge counts and coverage warnings. Explicitly mark the graph as a snapshot of the last indexing pass; it does not auto-update when files change. A user's manual re-index should occur with the viewer stopped initially: the current writer deletes/rebuilds the DB in place, so concurrent reads are not guaranteed. Later atomic rebuild/swap and reload can be designed separately. Failure states (missing DB, unsupported schema, unparsed file, missing source) must be explicit, never silently blank.

## Data and API boundary

All IDs are opaque graph keys, not URLs or filesystem paths to interpolate into commands. Requests accept only enumerated relations/commands, bounded integer depths, bounded page sizes, and repo-relative paths validated against the indexed File table. No arbitrary Cypher or arbitrary filesystem reads. Source text is optional and read only from a resolved regular file under the configured repo root (reject `..`, absolute paths, and symlink escapes via realpath containment); never expose `.git` or files outside the repo. Escape all displayed text in the DOM; do not render source or symbol names as HTML. Same-origin fetch only; localhost-only listener, reject hostile Host headers, disable permissive CORS, and avoid mutation endpoints. Keep conservative response-size and traversal bounds so a large graph cannot lock the browser.

Proposed internal endpoints (names may be refined without touching the v0.1 CLI):

- `GET /api/meta`: schema/index metadata, counts, language coverage, warnings.
- `GET /api/files?prefix=&cursor=&limit=`: bounded tree children and per-file parse/language/count summaries; `GET /api/file?path=`: file metadata and paginated symbols in definition order.
- `GET /api/symbols?q=&file=&cursor=&limit=`: bounded name/qualified-name search with all matches retained (no silent ambiguous pick); `GET /api/symbol?id=`: definition, parent, children, declaration citation and edge counts.
- `GET /api/neighborhood?id=&relations=calls,references,inherits&direction=both&depth=1&limit=`: a bounded node/edge slice. Each edge includes type, source/target IDs, confidence and reason when present, site `file:line` (column remains in the stored edge but is not exposed by this initial API), plus declaration citation. Preserve parallel call sites rather than merging their evidence. Imported file links can appear separately; do not imply unsupported cross-language links.
- `GET /api/query?command=callers|inherits|dead-code|blast&...`: invoke existing query functions, then paginate/slice presentation without changing semantics. Return resolved symbols and full result rows with their existing `citation`, `confidence`, `depth`, and `target` fields. Use the same default depths and filters as the CLI. A broad dead-code result needs server-side paging; avoid doing a full expensive scan on every keystroke and cache by index snapshot if useful.
- `GET /api/source?path=&start=&end=`: bounded lines around a cited location, no writes; unavailable source is shown as a citation without a preview.

A UI-specific response envelope may have pagination and stale/error fields, but must not be substituted for or alter CLI `--json` / harness `answers`. Use parameterized Cypher for selectors and whitelisted relationship names. Stable ordering by path, line, ID and edge-site position ensures repeatable views. Cap depth (for example 3) and returned nodes/edges (for example 200 each) in graph drawing; show truncation and offer drill-in instead of silently dropping data. Unbounded CLI depth 0 remains CLI-only until a deliberate UI affordance exists.

## Core views and navigation

1. **Explorer:** left file tree with language/parsed badges, search by symbol name, center symbol/file detail, right contextual actions. Unparsed Shell, Smali, Kotlin and other files are visible as files with a coverage warning, not invented symbols. A file lists its symbols and declaration citations; a symbol card shows kind, qualified name, location, parent/children, and confidence-labeled connections. Browser back/forward and copyable local URL preserve selected file/symbol, query, filters and depth using URL parameters or hash; encode IDs safely.
2. **Graph canvas:** focused subgraph around the selected symbol, initially one hop, directed arrows, a legend for CALLS/REFERENCES/INHERITS (and optionally containment/imports, visibly distinct). Exact and heuristic edges have different line styles with text labels, not color alone. Select a node to drill in; select an edge to see every site, confidence/reason and clickable `file:line` citations. Cluster or list overflow rather than rendering the entire repository. Keyboard focus and a companion edge list make the graph usable without relying on spatial layout.
3. **Results panel:** tabs for callers, inherits (descendants/ancestors), dead-code (likely/possible, kind/scope filters) and blast (file or symbol, depth). Reuse v0.1 definitions and result citations exactly. Show resolved target(s), count, filters, a list/table grouped by file, confidence and depth badges, and a one-click path from result to symbol, evidence edge, and bounded source preview. Label dead-code as candidate analysis, not proof of safety; blast is potential impact, not certain breakage. No code changes or automatic actions.
4. **Coverage/status:** index timestamp/commit, schema, parser coverage, edge counts, parse errors, limits. Persistent small notice when viewed source/HEAD differs from indexed commit or file is missing; precise per-file drift detection is a later enhancement. Do not imply a live graph while looking at an old snapshot.

Layout: resizable navigation and detail panes on desktop; stacked panes and a list-first graph fallback on small screens. Long names wrap or truncate with full accessible text. Cite every result and each edge's evidence, not just the graph node. Opening a citation shows a small source excerpt with line numbers and highlights; keep provenance distinguishable between a declaration line and a use site. No link from a local citation to an assumed public remote URL.

## Build plan and acceptance checks

1. **Read-only data adapter + tests:** wrap `store.connect` and `queries`, add parameterized paged browse/neighborhood reads; exact/heuristic edge evidence preserved, ambiguous symbols surfaced, stable sort and bounds tested on tiny Python/Java fixtures. Verify schema version 1 and handle absent DB/source.
2. **Local HTTP layer:** serve bundled static files and allowlisted GET JSON routes, strict parameter/path/Host validation, loopback-only bind, no CORS or writes; test traversal and symlink escape, malicious symbol text, huge limits/depth, and HTTP errors. Avoid any reindex endpoint in this phase.
3. **Explorer UI:** implement file tree, symbol search/detail and query result panels, then bounded graph with evidence drawer and keyboard-accessible list fallback. Keep URLs navigable and browser history meaningful. Add loading, empty, truncated and stale states.
4. **End-to-end checks:** index small fixture and Rambler-Bangla, launch locally, compare each result view and citations with the existing CLI JSON; inspect actual browser pixels at desktop and mobile sizes, test keyboard navigation and long/hostile labels, check rendering and response times on Rambler-Bangla. Re-run nine unit tests and the frozen eval harness: CLI answers and scores must remain unchanged. Record the chosen limits, observed timings, and any incomplete source preview behavior. Do not promote a UI demo to evidence that unsupported languages/edges work.

Non-goals for this phase: cloud hosting, collaboration, auth/remote access, code editing, live file watching, graph-wide force layout, cross-language inference, Shell/Smali/Kotlin parsing, or any LLM answer path.

## Implemented interface freeze (2026-09-25)

The server currently exposes the GET routes listed under Data and API above with these concrete parameter names: `/api/meta`; `/api/files?prefix=&limit=&cursor=`; `/api/file?path=&limit=&cursor=`; `/api/symbols?q=&file=&limit=&cursor=`; `/api/symbol?id=`; `/api/neighborhood?id=&direction=in|out|both&relations=CALLS,REFERENCES,INHERITS&limit=`; `/api/query?command=callers|inherits|dead-code|blast&target=&file=&scope=&depth=&ancestors=true|false&kind=&confidence=&limit=&cursor=`; `/api/source?path=&start=&end=`. Pagination envelope is `{items, total, next, truncated}` on file/symbol lists; query `results` additionally has `next_url`. `cursor` and `next` are zero-based decimal offsets. `next_url` is a same-origin relative API path on query results for independent checkers; it is null at the end. `limit` ranges from 1 to 100, default 50. Query response is `{command, resolved, results:{...}}`, retaining exact CLI result rows and resolved array. Missing selector is 400; an indexed target not found is 404. UI graph is one hop, capped to 100 edges and up to 200 nodes, with `total_edges` and `truncated`. API graph evidence has `source`, `target`, `type`, `file`, `line`, `confidence`, `reason`/`relation`, `source_def`, `target_def`.

The browser selects an exact symbol ID (`path::qualname[/arity]`); the existing CLI resolver accepts it as `target`, so ambiguity is not silently picked. Typed user text still uses CLI resolution, including all ambiguous matches. UI exposes callers/blast depth 1-3, inherits depth 1-3 and ancestors toggle; CLI inherits depth 0 (unbounded) remains CLI-only. The UI uses scope and dead-code kind/confidence filters. Meta includes indexed commit/time/root/stats plus `current_head`, `indexed_commit` (alias of `repo_commit`), commit mismatch, working-tree modification and `snapshot_stale`. Freshness is a coarse repo-wide signal, not per-file hashing: if no Git HEAD is available, the interface cannot prove unchanged source. Stop viewer before reindex.

Implementation note: initial data adapter fetches ordered rows before slicing to page. The HTTP response and graph rendering are capped; very large graphs can still spend time materializing rows. A future iteration should push deterministic page limits into Cypher and cache expensive dead-code scans. This performance limit is not a claim of bounded database work.

## Acceptance evidence and known gaps

The fixture for the CLI parity inventory is `tests/fixtures/mini` (five files); Rambler-Bangla is pinned to `6caeb8d565952f4a4b61a062cbbf739e09ca9fc8`. The independent matrix manifest and frozen harness wrapper live in the test evidence bundle, not in the runtime package. The UI selector uses an exact ID when a node is clicked; a manually entered bare/qualified name retains the CLI's multi-match behavior. The initial HTTP graph endpoint is one hop and materializes all adjacent edge rows before slicing; it is response-bounded, not guaranteed DB-work-bounded. The UI shows a truncation note and lets the user drill into another node, but does not yet paginate all parallel sites in one focused graph. Source freshness uses Git HEAD and tracked working-tree status, not content hashes; no-Git freshness is unknown, so the screen calls it a snapshot rather than live. Source paths go through both indexed-File membership and realpath containment. A regression test replaces an already indexed regular file with an outside symlink in a disposable fixture to exercise the latter check independently.

The original nine tests are run separately from the new explorer tests. The frozen harness is the 20-question `harness3/questions.jsonl` (SHA-256 `362ffcb5cdc2d53c181f43c596144ce23fad0a4dcffa9b60c99cd32ba32d679b`). ### Source containment scope (review note)

In the current route allowlist, `/api/source` is the only endpoint that opens repository source bytes. This follows an inspection of `explorer_server.py` and `explorer_data.py`: the static routes read packaged UI assets; `/api/file`, `/api/symbol` and graph/query routes return indexed metadata. This is a code-surface observation, not an independently certified exhaustive security claim. `Explorer.source` checks indexed File membership, resolves a regular file under the repo root, then opens it. The unit test and HTTP route test both index a regular `app.py`, replace it with an escaping symlink, verify the indexed row still exists, and get a NotFound/404 before source bytes can be returned. A symlink already present before indexing is skipped by `discover.py`, so it cannot reach the source route through the normal indexer; this is a separate unexercised branch, not a general safety proof. A narrow time-of-check/time-of-use window remains between `resolve()` and `open()`: an adversary able to swap files inside the repo while the viewer is serving could redirect the open after containment validation. The intended v0.2 use is a trusted local repo with a loopback listener, but the check is not race-free. Hardening would open through a no-follow, directory-relative file-descriptor walk and validate the opened object rather than a prior path; that is future work. Do not expose this server remotely or treat the current containment as a sandbox against an actively malicious local writer.
